# Fabric Efficiency Ledger - systems boundary

This document states exactly what the runtime owns, what it refuses to do, and
which mechanism enforces each refusal. It is the contract a reviewer should hold
the implementation to.

## 1. Owned

The runtime owns *deterministic accounting of useful network work versus
non-useful or avoidable resource consumption*. Concretely:

* Deciding, from evidence and policy alone, which accounting cell a measured
  quantity belongs to.
* Deciding whether two pieces of evidence describe the same physical
  measurement, and refusing to count both when they do.
* Deciding whether a quantity may be counted at all, and saying exactly why not
  when it may not.
* Checking that the classified totals agree with independently reported totals,
  and reporting the difference when they do not.
* Publishing an immutable, content-addressed record of a closed accounting
  period, with a linear correction lineage.
* Explaining any published number in terms of the evidence and the policy rules
  that produced it.

## 2. Refused, and how the refusal is enforced

| Refused | Enforcement |
| --- | --- |
| Scheduling or shaping traffic | There is no API that emits, queues or delays a packet or a descriptor. The runtime has no network, socket or device handle of any kind. |
| Controlling routing or path selection | Paths are declared facts in the topology. The runtime reads them to attribute evidence; it never selects a path. `FabricTopology::add_path` stores hops and nothing consumes them for control. |
| Enforcing quotas or admission control | `Reservation` records capacity that an operator declares. The runtime accounts for idle and stranded reservation time; it never admits, rejects or throttles work. |
| Inferring monetary cost | No cost field exists anywhere in the policy, the observation schema, the claim schema or the results. `MeasureKind` enumerates octets, nanoseconds, messages and frames only. |
| Inferring efficiency from missing telemetry | A quantity that was not measured increments an unmeasured counter, never a total. `AggregateCell::coverage()` reports `unknown`, and `EfficiencySummary::determinate` is false whenever anything is unmeasured, unclassified or unverifiable. |
| Treating absence of evidence as zero | A domain with no observations produces no claims at all, and its efficiency summary has `denominator == 0` with `coverage == unknown`. Nothing is published as `0` on the strength of silence. |
| Guessing a value from conflicting evidence | `ConflictPolicy::RecordAndUnknown` is the default: the cell becomes unknown and both participants are explained. A resolution policy exists but is opt-in and is always recorded. |
| Silently netting a residual | A residual is recorded in the unknown bucket with reason `residual-unclassified` and is never added to a category. Over-attribution is reported and the period is flagged as not conserved. |
| Silently dropping evidence | Every rejection appears in the ingest report, in `PeriodRevision::rejected`, and in the explicit unknown bucket with a specific reason. |
| Silently truncating a result | Every list-shaped result carries a `Truncation` with the total available, the number returned and a reason. |
| Silently wrapping an arithmetic result | Every accumulation uses checked arithmetic and reports `ArithmeticOverflow`. |
| Silently promoting persisted evidence to fresh | Freshness is always evaluated against an explicit `as_of` instant. Reopening a store with a later `as_of` correctly expires the stored evidence. |
| Silently attaching stale-generation usage to current resources | Correlation requires a generation binding that covers the observation time. Evidence for a superseded generation is fenced as `stale-generation`. |
| Multi-writer or clustered operation | One store holds an exclusive OS-level lock for the lifetime of the store object. A second writer is refused with `StoreLocked`, proven across independent processes. |

## 3. Claims about hardware and telemetry

The runtime makes **no** claim about any switch, ASIC, RDMA, InfiniBand, NVLink,
multi-host or hardware telemetry source. No such device was available during
development, and none of the tests, benchmarks or examples touch one.

The `ProvenanceClass` mechanism exists precisely so that this honesty is
machine-checkable:

* `real` - measured by a reporting agent;
* `synthetic` - generated by a model, a simulator or the test harness;
* `replay` - replayed from an archive;
* `unsupported` - declared, recorded, and **never counted**, whatever its
  declared authority.

Every result carries the set of classes that contributed, and
`ProvenanceStamp::purely_real()` is true only when measured telemetry alone
produced it. A deployment that ingests only `synthetic` evidence will see
`synthetic` on every result; it cannot accidentally present a simulation as
measurement.

## 4. What a consumer must supply

* A topology document that declares the fabric's scopes, resources, sources,
  source incarnations, generations and generation bindings.
* A policy document that states the freshness budget, the conflict, residual,
  excess and late-evidence policies, and the resource bounds.
* Evidence documents whose records state, for every measurement, what was
  observed, by which source and incarnation, for which generation, at which
  observation and receive times, under which epoch and sequence, over which
  reporting window, and with which provenance it was produced.
* Optionally, independent total observations that let conservation become a
  proof rather than a statement.

The runtime will not fill any of these in from a default, a guess or a clock.

## 5. Failure modes the runtime cannot defend against

* A source that systematically under-reports and never contradicts itself. Only
  an independent total can catch this, and only if an operator supplies one.
* A source that reports plausible but entirely fabricated numbers consistently
  within the same provenance class. Conservation against a well-chosen total is
  the only lever.
* A topology that mis-declares which scope a resource belongs to. Accounting
  remains internally consistent; it is simply attributed to the wrong scope.
* A policy whose freshness budget is far wider than the reporting cadence. The
  runtime applies the policy faithfully; the operator owns its suitability. The
  policy revision is recorded in every result so that this is auditable.
